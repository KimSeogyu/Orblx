# Orblx 0.1.0-rc.3

This note is the skeleton for release 0.1.0-rc.3.
The tag is not cut.
The version on main is `0.1.0-rc.3-dev`.

## Highlights

- Main builds print `0.1.0-rc.3-dev`. A main build does not print a release version.
- Subnet routers can fail over. The client keeps the same router while that router is up.
- The node closes the packet gap at SVID renewal.
- The SSH server reads the current node key for each connection.
- The release workflow can build Linux amd64 and arm64 binaries, the amd64 image, the arm64 image, and SHA256 checksums in a dry run.

## Changes

The changes are the pull requests on main after tag `v0.1.0-rc.2`.
The list is in `CHANGELOG.md`.

## Install

The install command for a published tag is:

```sh
curl -fsSL https://github.com/KimSeogyu/Orblx/releases/download/v0.1.0-rc.3/install.sh | sh -s -- --version v0.1.0-rc.3
```

The tag `v0.1.0-rc.3` does not exist yet. Do not run that command against a public release until the tag exists.

A dry run does not publish a GitHub release. A dry run does not push an image to a registry.
Use the dry-run files, or a local file server, with `scripts/release/install-e2e.sh`.

The end-to-end test runs in a clean Ubuntu 24.04 container.
The container has `NET_ADMIN` and `/dev/net/tun`.
`orblx up` opens a TUN device.
The test does not use the sim harness.

## Upgrade

1. Keep the `0.1.0-rc.2` binary until the `v0.1.0-rc.3` tag exists.
2. After the tag exists, run the install command in the Install section.
3. Run `orblx down` before you replace a running node binary.
4. Start the node again with `orblx up`.
5. Do not install a `-dev` build as the release binary.

## Known issues

### rc.1 and rc.2 carry-over

rc.1/rc.2: about 1 min after a node's capability ticket ends (the ticket life is the SVID life, about 16 min by default), its peers refuse it (end time has passed). New connections and existing sessions with traffic both stop. Workaround: restart the node (orblx up).

rc.1/rc.2: A node that sleeps or pauses longer than its SVID life plus 1 min (about 16 min by default) cannot reconnect, and a restart does not help. Enroll it again under a new node name with a new enroll token or pre-auth key (orblx admin preauth-create, then orblx coord enroll). The old node name cannot be enrolled again in this release. Policy rules and grants for the old name do not apply to the new name: update them, and revoke the old node.

SSH logins can fail after the node certificate renews (W25-40). A fix is merged (#137) but is not yet proven on a real host. Open in rc.3.

rc.1/rc.2 SSH login has no netmap age check and no cert serial; a node removed from the netmap but not on the deny list can still log in until its SVID expires. Upgrade to rc.3.
